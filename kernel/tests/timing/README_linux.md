# Linux/AArch64 固定输入软件时序检查

`run_linux.py` 与 `screen_linux.c` 提供 Linux/AArch64 时序检查；输出保存编译、功能预检与采样状态。运行依赖 Python 3、NumPy、GCC 和 binutils，准备阶段以 NumPy PCG64 固定计划次序，不能无说明地更换生成器。

`prepare --dll <实际库.so> --source-root <冻结工程源> --output <新目录> --cpu 2` 检查同一 ELF64/AArch64 文件的符号和可执行 PT_LOAD 段，编译检查驱动并保存预登记计划。驱动用绝对路径加载库，通过 `dlinfo` 获得加载基址，以其加同一文件的符号值定位私有 C 包装入口，并通过 `dladdr` 和 `realpath` 核对实际映像。缺少所需入口就停止，不从相近符号猜测地址，不额外编译替代内核。

`validate --output <上述目录>` 使用样本数零执行数学及接口预检，不采集时序。`collect` 需要同一冻结计划、已完成的预检和新的独占协调令牌。KEM 主组与 `--keccak-family dsa --only-keccak` 附加组分别绑定两个家族的实际代码副本。

测量使用固定 CPU 的 `CLOCK_MONOTONIC_RAW`，原始单位为纳秒。每次读时钟前后有 AArch64 `dsb ish; isb`，其固定开销保留在观测中；这些值不是 CPU 周期。原始三列为类别、纳秒和返回的范数标志。保留三个固定种子、每族十万样本、五个预定检查点、均值及中心化二阶矩 Welch t；不删尾部、不因显著提前停、不自动重跑。阳性包装器根据输入秘密派生比特执行明显延时，必须在实际采样后检出，才能支持检测流程有效的结论。

四类解封装输入保持分别报告：合法生成密钥池、仅秘密 z 改变、公开密文诊断、固定公开部分的 dk_PKE 算术域诊断。最后一类不是匹配的标准生成密钥对。合法密钥池也改变嵌入公钥及公开 rho，因此显著结果必须保留并调查，不能直接归为秘密泄漏。

NTT 使用 eta 秘密系数及 gamma1 临时掩码的合法算术范围，逐点乘检查实际 Montgomery 域关系；完整签名的自然拒绝重试不属于这些内核检查。小模/CRT 兼容代码不注册且在入口拒绝，不能形成该路径覆盖声明。结果按所列程序和输入域解释。
