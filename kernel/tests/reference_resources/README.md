# 参考实现的完整内存测量

测量对象是已构建的公共算法库。库文件的 SHA-256 与配置文件核对后，测量程序加载原文件，分别执行六组参数的三项完整操作。Windows 通过导入表拦截分配函数；Linux 使用 glibc 分配函数代理。测量程序及拦截代码均位于独立测试程序中。

每项操作先用三个固定种子测量栈使用量，将最大值向上取整到 256 字节，再增加 256 字节余量；随后用 24 个独立种子在该固定容量下复核。栈下方设置不可访问区域。空调用、超限调用和堆分配用于检查测量工具。单项记录保存容量、栈标记、工作区、堆调用、清理、完整结果比较和返回状态。

预留内存由调用者工作区、受保护栈、上下文、可写映像、单线程 TLS 以及实测堆请求峰值相加得到。六参数共用配置取各组成部分的最大值。该值是容量预留；各部分的最大使用时刻可以不同。密钥、消息、密文及签名缓冲区另列。虚拟映射、操作系统提交页与算法预留内存分别记录。

PQClean 保持其原有自动数组与堆分配。适配接口要求一个非空工作区，本测试提供 32 字节，算法实际工作区用量为 0。Windows 的分配统计从工作线程启动延续到线程析构；Linux 统计完整密码调用。Windows GCC 库使用 MinGW 的模拟 TLS，工作线程会产生额外运行库分配。其 480 字节保留块对应 `pop_pthread_mem` 中的线程记录池，返回地址相对库起始地址为 `0x34af`，已计入堆峰值。Clang 库采用的 TLS 路径不同，两者分别测量。

运行方式：

```text
python tests/reference_resources/run.py --config libraries.xml --output new-results --cc gcc
```

配置文件的 `libraries` 数组包含 `id`、`path` 和 `sha256`。输出目录必须尚未存在。输出包含源文件副本、工具及库的校验值、全部逐次记录、编译日志、工具控制结果与汇总。计时数据应使用独立性能测试获取。
