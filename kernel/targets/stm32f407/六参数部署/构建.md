# STM32F407 完整固件复建

每个 BIN 包含 ML-KEM-512、768、1024 和 ML-DSA-44、65、87 的密钥生成、封装或签名、解封或验签，共 18 项。USB 协议保留六组参数的 compact 和 cached 两个请求键。24 KiB 设备可以按参数让这两个请求键共用符合该预算的实现。选择后端和保留缓冲区发生在构建时。

完整构建输入在 targets。sources.sha256 记录该目录和 licenses 的文件摘要。展开后的 C、汇编、符号重命名、链接脚本、完整标准测试向量及链接顺序由配置清单固定。compiler 内生成面向 Cortex-M4 的参数化签名调度、工作区查询和公开向量存储表示。构建同时输出 ELF、BIN、MAP、运行描述 XML、逐个编译单元的源摘要和对象摘要。

## Windows 构建

准备 Python 3.11 或更新版、Android NDK 26.1.10909125 的 LLVM 17.0.2、GNU Arm Embedded 13.2.rel1 的汇编器。以下路径请替换为本机实际位置。固件输出目录放在 targets 以外。

~~~powershell
$env:LLVM_BIN = 'C:\toolchains\llvm\bin'
$env:ARM_AS = 'C:\toolchains\arm-gnu\bin\arm-none-eabi-as.exe'
py -3.13 -B .\compiler\build.py 24 --reference --compact-image --output .\out\reference24
py -3.13 -B .\compiler\build.py 24 --all-operation-cache --optimize-compact-dispatch --compact-stack --mont-product --compact-image --output .\out\m4-24
py -3.13 -B .\compiler\build.py 28 --all-operation-cache --sign-key-cache --mont-product --compact-image --output .\out\m4-28
py -3.13 -B .\compiler\build.py 32 --all-operation-cache --frontier matrix5 --grouped-mask --mont-product --compact-image --output .\out\m4-32
~~~

32 KiB 的 matrix5 构型保存五个完整的公开矩阵多项式。完整保留一项可以在后续重试时跳过整次展开。比较实验使用 --sign-key-cache、--frontier triple3、--frontier triple4 或 --frontier matrix85 替换 --frontier matrix5。triple3 和 triple4 使前三行或四行按三个候选展开，其余行按两个候选展开。matrix85 与 triple4 的专用分配均为 4096 B，matrix85 保存五个完整项和下一项的前 85 个系数。

## 存储和运行

镜像加载地址是 0x08020000。SRAM 链接区域从 0x20008000 开始，包含 USB 和启动状态、事务输入输出、算法工作区、调用栈及保护区。启动描述中的 full_reserved_ram_bytes 为这些项目的合计，ram_budget_bytes 是链接器强制执行的预算。每一配置使用相同 SHA-256 锁定的 ELF 与 BIN。设备返回执行中 Flash 的 SHA-256、芯片 UID、时钟和每个操作的工作区与栈观测值。

低内存签名在候选验收前使用签名输出存放当前掩码的变换列，其他列和部分已分解行放在工作区。高性能签名将下一候选的部分行放在输出区，其余行放在独立工作区。检查 z 的绝对值、低位、提示权重的顺序与原代码相同。确定候选通过后，重新构造并编码 z，生成标准签名。剩余尚未产生的候选不影响接受次序。

公开测试夹具的压缩保存、重建和逐字节比较使用与生产内核不同的参考运算。对照使用同一批原始标准样例、驱动、时钟和请求协议。参考固件在空闲固定栈内展开夹具。项目固件在生产调用前后使用空闲工作区。NIST 测试向量均为公开数据。许可与代码来源保存在 licenses。
