# STM32F407 固件维护

日常运行打开支撑材料根目录的 `Quantum Kernel.exe`。从 ROM 启动时，软件先检查板上的固件，再启动应用。六组参数与两档策略共用一个 USB 连接。

维护命令在源码工程根目录运行。Windows 安装 STM32CubeProgrammer 后，用板上的 USB 数据口连接电脑。默认板 UID 为 `350048000D51353338393837`，ROM 序列为 `3780396D3335`。首次安装使用 ROM DFU；引导跳线和复位操作按该板丝印执行。

| 用途 | PowerShell 命令 |
|---|---|
| 只读检查 | `py -3 targets/stm32f407/maintenance.py check` |
| 首次安装 | `py -3 targets/stm32f407/maintenance.py install --backup-dir D:/F407原始固件备份` |
| 恢复原板 | `py -3 targets/stm32f407/maintenance.py restore --backup-dir D:/F407原始固件备份` |

备份目录使用支撑材料之外的新目录。安装前，工具把已校验的临时识别程序装入 SRAM，读取 96 位 UID、Cortex-M4 型号、0x413 设备组和 1 MiB Flash 容量，并通过 USB 帧校验时钟。ROM 读写命令绑定指定设备序列。备份内容包括原始整片固件、独立读取的扇区副本、此次安装的镜像和身份记录。

安装范围为 5、6、7 号扇区，地址区间为 `0x08020000–0x0807FFFF`。只有三个扇区全空且两次读取一致时才会写入。写入后逐字节比对整片 1 MiB；程序、保护区与未用空间都纳入核对。工具把板留在 ROM，Quantum Kernel 在首次连接时启动固件。

恢复时，工具重新核对设备、备份和现有全部 Flash。与原备份一致时直接结束。若只发现此次安装的已确认镜像，工具只清除原本全空的三个扇区，再读回全部字节。无法识别的新增数据会保留。更换同系列开发板时，通过 `--uid` 指定其真实 96 位 UID；空闲区域、USB 时钟和芯片能力须在这块板上重新通过检测。可用 `--cube-cli` 指定 STM32CubeProgrammer 命令行程序。
