# 矩阵存储与工作区复用

速度配置在一次标准调用内建立公开矩阵缓存，以相同矩阵服务签名的各次尝试。矩阵存储、矩阵乘法输出和采样临时区共同安排，目标是保留向量乘法效率，同时减少六组参数、十八项操作所需的共同预留空间。Windows使用AVX2，AArch64使用NEON；两平台分别与同平台、同编译条件的实现比较。

## 公开矩阵的16位与8位存储

ML-DSA公开矩阵的规范系数满足0≤a<8380417。每个多项式将256个系数的低16位连续存放，再连续存放256个高8位，合计768字节。读取时使用零扩展、左移16位和按位或，精确恢复32位规范系数。8个连续频点一次装入向量寄存器，恢复操作与随后的乘加衔接。

此布局保持标准系数与矩阵生成顺序。矩阵地址由公开参数、行列和系数序号决定；它在一次调用内复用，并随所属工作区释放。源码位于`src/dsa_packed/lc_a_planes24.h`，AVX2与NEON分别使用本平台的向量加载与整数指令。

## 先读后写的原位矩阵乘法

矩阵乘法的输入是L行NTT域掩码，输出是K行频域乘积。三组标准参数均满足K≥L。程序先在输出区的前L行保存变换后的输入，再按每块8个频点依次计算：读取当前块的全部L行输入，完成K行乘积，最后覆盖写入对应的K行输出。不同频点之间独立，当前块的覆盖不会改变下一块需要读取的输入。

每个输出行使用1024字节系数和32字节位图，行宽与后续分解一致。乘积使用64位累加，在每个输出系数完成点积后执行一次Montgomery约减；输入范围与约减界见[签名算术验证](signing_arithmetic.md)。秘密掩码和乘积继续按秘密对象处理，整块所属存储在成功和错误出口统一清理。实际AVX2辅助函数位于`src/dsa_packed/lc_inplace_ay.h`，NEON调用衔接位于`src/dsa_packed/lc_speed32_neon.h`。

## 同时安排工作区与调用栈

六参数库的共同运行内存分别取各操作工作区和栈需求的最大值，再加入上下文、可写全局区和相关堆。最大工作区与最大栈可能来自不同操作，因此局部减少一个数组后，还需检查整库共同容量。

当签名的矩阵缓存决定共同工作区W时，密钥生成和验签的四路采样临时区可以迁入本操作的工作区余量。设操作o原有工作区为w_o、迁入临时区为t_o，在w_o+t_o≤W时，迁移保持共同工作区不变，同时减小调用栈需求。采样状态、种子和暂存输出按固定参数分配；每批用完后清理整个对象，再逆序归还工作区。

ML-DSA分别安排秘密eta采样与公开矩阵采样，输入种子的内部子视图与输出区采用明确的归属关系。AArch64的ML-KEM-768还将公开矩阵生成、四路噪声及末尾单多项式的暂存对象纳入同一生命周期安排。四路状态完成后才复用其存储执行尾项，SHAKE输入、域分离、输出顺序和清理范围保持标准定义。

## 方法来源与本作实现

24位多项式表示、按需矩阵生成、稀疏挑战乘法、NTT和Montgomery约减已有研究与成熟实现基础。低内存Dilithium研究中的逐段处理与紧凑存储提供了相关方法依据；原生NTT及Keccak内核沿用随附上游实现的署名和许可，详见[来源与许可](sources_and_licenses.md)。

本作的具体增量是将低16位与高8位连续平面接入AVX2和NEON点积，把“当前8个频点的全部L输入先读完”作为覆盖条件，并将采样临时区放入非签名操作的共同工作区余量。三项安排分别改变矩阵缓存字节数、输入输出同时驻留量和跨操作预留栈；其联合结果由相同编译条件的完整操作与资源比较验证。

分离存储控制使用32位矩阵和独立变换向量，具体计算组织由对应配置及编译记录确定。该控制与速度配置一同参与十三种实现的完整操作比较及十种配置的完整应用比较；分项消融另按被修改的机制设置配对。时间、工作区、栈、程序空间和应用内存分别引用对应实际库的记录；每项数据可按库文件摘要连接到原始观测与源码。
