# ML-DSA签名的计算规则与安全验证

六组参数共享公开接口；ML-DSA的三组参数分别保持标准规定的挑战重量、范数界、提示数量界、消息与上下文编码，以及逐次候选的生成顺序。完整签名比较固定密钥、消息、上下文和随机输入，检查整个签名字节串及熵接口调用。

## 秘密数据与可观察信息

签名首先由掩码向量计算矩阵乘积，再从完整高位编码生成挑战。秘密多项式、掩码、乘积低位和检查前的提示状态均按固定位置存储。挑战生成后，稀疏乘法按其非零位置和符号读取秘密多项式；给定挑战，访问下标由参数、输出位置和挑战索引确定。

签名安全归约以标准密钥生成算法产生的公钥和攻击者获得的签名查询输出为对象。Barbosa等修正Fiat-Shamir with aborts的CMA到NMA归约，并机械化验证ROM中的证明；Fallahpour等在量子随机预言机模型中进一步收紧归约损失。两项研究使用接受条件下的诚实验证者零知识性质（acHVZK），模拟以接受为条件的转录分布；具体界还涉及承诺的最大概率、拒绝概率及模拟误差。实现中的控制流和地址轨迹按下述软件观察模型另行分析。

接受尝试的挑战可由最终签名计算。对拒绝尝试，[CRYSTALS-Dilithium规范第5.5节](https://pq-crystals.org/dilithium/data/dilithium-specification-round3-20210208.pdf)在挑战哈希的随机预言机模型和高位向量高最小熵条件下讨论挑战公开，并依据拒绝采样的分布条件允许观察拒绝原因及范数首失败位置。本实现采用逐多项式固定扫描，公开粒度为检查结果及相应阶段、行。给定这些允许公开量，稀疏算术的地址由挑战索引与固定输出位置确定；秘密系数值、被拒绝的响应数值和未接受的提示向量继续保持秘密标记。

Zhou等通过被拒绝响应与挑战的联合侧信道信息恢复Dilithium秘密，所展示的物理攻击利用Cortex-M4功耗。该研究明确了拒绝候选数值的保护需求。本实现将接受转录、规范允许的拒绝结果和内部秘密数值分别标记，并按实际数据路径检查秘密算术、分支与地址依赖。

| 计算阶段 | 保持秘密标记的数据 | 按分析模型公开的信息 |
|---|---|---|
| 私钥编码检查 | 私钥全部编码字节 | 完整扫描后得到的一个合法性结果 |
| 掩码与矩阵乘积 | 掩码、NTT掩码及乘积低位 | 参数、候选序号、公开矩阵种子与矩阵索引 |
| 挑战稀疏乘法 | 秘密系数与中间累加值 | 挑战支持集、符号和相应分组长度 |
| 范数检查 | 每个多项式内的256个系数 | 完整扫描后的检查结果；逐行配置还公开首个失败行及所属阶段 |
| 提示形成与重量检查 | 全部接受条件通过前的提示谓词、位置与累计数量 | 固定扫描后得到的重量超限布尔结果 |
| 接受后的提示编码 | 已拒绝候选及其他尚未使用的秘密状态 | 已接受提示的位置、累计数量和序列化输出 |

AArch64高性能策略在公开 `lc_sign` 入口请求随机字节前，调用 `lc_dsa_secret_encoding_valid` 完整扫描私钥的 $s_1,s_2$ 编码。44与87的字段宽为3位，合法码为0至4；65的字段宽为4位，合法码为0至8。每个字段的最高位与其余位同时非零时，分别判定为非法编码5至7或9至15。实现用 `0x924924` 或 `0x88` 保留各字段的最高位，再对全部编码组按位或汇总；扫描长度与地址只由公开参数决定。

该函数在整个编码区扫描结束后返回一个合法性布尔值。接口仅依据这一结果决定是否继续请求随机字节，非法私钥清零签名输出并返回拒绝；私钥字节与系数保持秘密。独立测试在每个系数位置遍历全部码值，分别使用0和合法最大值作为其余字段背景，并检查编码区末端保护页及随机字节输入，共185088项。三字节谓词另穷举全部 $2^{24}$ 个输入，四位谓词穷举全部256种字节值。

提示形成使用固定位置位图和掩码谓词。所有范数检查通过后，`lc_check_hint_weight_before_disclosure`先计算完整提示重量：已形成位图的配置固定读取每行32字节，使用移位与掩码累计置位数；延迟形成提示的配置固定遍历每行256个系数，计算并累加相同谓词。总重量至多为$256K$，循环次数和地址由参数及行宽确定。程序只公开“重量大于$\omega$”的布尔值，超限即清理并进入下一尝试；通过后才公开提示编码所需值，执行按位置写入的序列化。由此，变址编码位于全部接受条件之后。

## 表示、运算与检查粒度

### 紧凑低位与高位位图

低位压缩依据系数范围选择18、19或20位表示，解码按最高位恢复符号。分组长度、行宽和读写位置由参数确定。高位先完整进入挑战哈希，后续提示判断只需保留高位是否为零，每行使用256位位图。位图更新在尚可能发生后续拒绝的阶段执行，使用整数掩码合成结果。

提示谓词在标准分解范围及相关范数条件下，与标准MakeHint逐系数等价。验证分别覆盖低位往返、原地压缩、边界值、完整高位哈希输入、提示重量边界和谓词等价条件。对超出数学前提的输入，数据集保留对应比较结果和输入范围。

速度配置按平台和公开参数选择矩阵表示。Windows的ML-DSA-44、65直接保存32位规范系数，ML-DSA-87将系数分为低16位和高8位；AArch64三组参数采用相同的分平面表示。分平面恢复使用零扩展、移位和按位或，地址由矩阵索引和系数序号确定。参数选择在编译时确定，矩阵值始终来自公开种子。

矩阵乘积和低位采用32位行，每行1024字节系数加32字节位图；最初L行暂存秘密NTT掩码。每次处理8个频点，先读完全部L行对应输入，再覆盖写入K行输出。不同频点之间相互独立，三组参数均满足K≥L。读写次数、行宽及覆盖次序由公开参数决定，秘密数值继续受标记跟踪。整块存储由同一个工作区对象拥有，释放时清理实际分配的全部字节。

### 稀疏乘法与延迟约减

速度配置在一次签名调用开始时，固定扫描私钥中全部$s_1$、$s_2$编码，再以一个聚合布尔值选择累加范围。扫描的长度和地址由公开参数确定，全部合法私钥得到相同的合法性结果。公开接口先执行标准编码检查；内部算术入口仍保留完整编码域的处理分支。

对合法编码，$\eta=2$时每个系数的绝对值至多2，三组参数的挑战重量均至多60，因此完整挑战的任意部分和绝对值至多120，可在8位有符号表示中累计后统一扩展。$\eta=4$时按31项分组，8位部分和绝对值至多124，再扩展为16位合并。两平台都以同一个完整编码检查结果选择分组；NEON实现独立传递$\eta$和分组长度，解码规则由标准参数确定。

内部入口遇到非规范编码时，采用覆盖全部编码位模式的原分组：$\eta=2$按25项累计，部分和绝对值至多125；$\eta=4$按11项累计，部分和绝对值至多121。16位合并后的最大绝对值在44、65、87下分别为195、539和300。秘密系数和部分和持续标记为秘密，公开注解仅作用于完整扫描后的编码合法性结果。验证分别覆盖合法密钥、非规范编码、分组端点和完整签名字节。

挑战多项式与$t_0$相乘时，每7项的16位部分和绝对值至多28672，扩展后的完整和由挑战重量与4096的乘积约束。输入延拓区与输出区分开，读取下标由挑战位置和固定输出块决定。[FIPS 204第6.1节](https://nvlpubs.nist.gov/nistpubs/FIPS/NIST.FIPS.204.pdf)将完整$t$视为扩展公钥；实现仍按秘密对象的生命周期清理$t_0$存储。

矩阵点积先以64位累加原始乘积，再执行一次Montgomery约减。采用$q=8380417$、$L\leq7$及NTT输出界$|y_i|<94279698$，累加绝对值至多5530721568497664，小于$q2^{31}=17996808470921216$。AVX2与NEON实现分别验证带符号乘法、约减、存储和向量排列；完整签名字节比较将这些助手的模等价关系连接到公开操作结果。细节见[签名算术验证](signing_arithmetic.md)。

### 拒绝检查

两种正式策略均启用逐多项式拒绝。每个多项式的范数检查读取全部256个系数，再返回聚合结果；失败尝试可以在该多项式检查完成后退出。65、87依次检查响应、修正低位、$ct_0$与提示。高性能策略的44在响应检查通过后先检查全部四行修正低位，再计算$ct_0$与提示；低内存44沿用逐行衔接低位与$ct_0$的次序。各行固定扫描，失败阶段与首个失败行按所声明模型可观察。组件对照中的整向量聚合路径由各自编译记录单独定义。

Windows的低内存与高性能策略按需推迟挑战NTT。响应及可提前完成的修正低位检查使用系数域稀疏乘法，后续$ct_0$才使用变换后的挑战；低内存44在逐行检查首次需要$ct_0$时完成变换。提前结束的尝试省去尚未使用的NTT，接受条件和候选序号保持一致。AArch64的$ct_0$采用系数域稀疏乘法，保持该路径的挑战表示。

逐多项式退出使失败阶段和首个失败行可观察，并保持行内固定扫描。候选接受条件、检查阈值和提示数量界保持一致；这些条件决定首个被接受的候选。完整输出比较同时核对消息、上下文、随机字节和换键场景下的签名一致性。

## 缓存归属与退出清理

公开矩阵缓存属于一次签名调用。缓存值来自本次公开种子，只有所需条目全部写入后才设置有效状态；新调用重新初始化状态。不同密钥和不同调用的缓存归属由这一生命周期隔离。

48项缓存配置和速度配置借用调用方已经提供的签名输出区，保存当前尝试的掩码编码。掩码的标准编码与最终响应$z$采用相同的逐行长度，分别为44的2304字节、65的3200字节和87的4480字节。矩阵乘积先读取所需掩码；形成响应时，每行完整解码后再以$z$覆盖该行。所有成功输出行均完成覆盖。每次拒绝在返回重试循环前立即清零整个借用区域，包含尚未读取的掩码和已经写入的部分响应；外层错误返回还清零完整签名输出。该区域始终由调用方持有，容量与输入重叠检查在进入公开操作前完成。

Windows紧凑配置在ML-DSA-65、87首次生成掩码时，将原采样过程已经产生的字节同时保留到对应签名行，供后续响应计算读取。65保持矩阵与下一列掩码的原交错次序，87保持原单路掩码生成次序；完成整个矩阵乘积后，公开阶段标志切换为“全部行已生成”。采样种子、nonce、输出字节和候选顺序保持一致。44继续使用原工作区掩码对象。借用区域中的掩码按秘密数据处理，拒绝清理规则与48项缓存和速度配置一致。

24位表示、按需计算及签名输出区复用已有Dilithium低内存实现基础。本实现具体安排当前掩码编码与响应行的先后使用，并将逐次拒绝清理纳入同一生命周期；相关依据见[签名算术说明](signing_arithmetic.md)。

跨尝试掩码队列保存同一次调用后续候选所需的随机多项式。有效项携带对应的公开nonce位置，消费顺序与标准候选序列一致。给定参数和允许公开的尝试轨迹，组起点、有效通道数、队列下标和消费次序均由这些公开量确定；掩码输出值保持秘密。四路计算末尾用于补齐的虚拟通道仅参与计算，队列有效长度只计算实际所需项，nonce边界限制有效项的生成范围。成功、错误、容量不足和暂停出口均释放并清理整个所属对象，包括尚未消费的掩码。

Windows的ML-DSA-65还将最后两条公开矩阵流与前两条秘密掩码流组合计算。各通道分别使用SHAKE128和SHAKE256规定的输入、填充位置与输出速率。矩阵生成至少执行5轮置换，640字节掩码也需5轮；公共拒绝采样增加的轮次继续服务矩阵，掩码写入在640字节处结束。实际AVX2指令按四条独立来源标记传播，逐项检查通道内移位、置换常数、状态地址和24轮公开计数；每条输出流保持对应输入流的来源。联合调用保留秘密通道的标记。

ARM原生eta采样使用576字节栈暂存区。输出复制完成后，函数执行18次32字节存零，再恢复栈指针并返回原接受数量。专用检查在真实汇编函数返回后立即读取该区，固定38项输入分别检查接受数量、全部256个输出系数、上下边界哨兵和576字节清零；生产共享库与检查程序的函数机器码逐字节对应。Windows对应采样函数通过寄存器向输出区写入，函数内使用的存储方式另由实际机器码记录。

四路采样的临时状态和输出暂存区由当前调用的工作区分配，尺寸只取决于公开参数。秘密eta种子、采样字节与接受系数保持秘密属性；公开矩阵种子与矩阵采样数据按公开属性处理。输入种子的内部子视图与输出区有明确归属，计算时保持所需的不重叠关系。每组采样完成后清理整个临时对象，包括对齐填充及未使用通道；分配失败按逆序释放已有对象，清理有效输出并返回容量错误。释放前观察检查逐个注入实际分配位置的失败，再在同一上下文中恢复并逐字节比较完整输出，见[分配失败与清理检查](../tests/owner_boundaries/README.md)。

## 分项证据与配置对应

验证记录将源码、编译条件、库摘要、原始输出和统计单位逐项关联。接口比较使用正常生产库；内存检查和秘密传播检查使用各自的插桩构建，并通过输出比较连接到生产构建。

两种正式策略的签名路径证据位于准备后的复现工作目录`data/upgrade-20261016/artifacts`下。ARM低内存的记录见`acceptance-security-arm-01`；高性能两容量见`recovery-arm-compact-02/security/result.xml`，绑定生产库SHA-256 `91ba14c3d7953745729a6ec06920b23ffafcd571d5b4279c9c452f58bbab173f`。高性能两容量合计96次签名、6次容量恢复通过秘密传播与生产输出比较，加上低内存共144次签名、9次恢复。插桩仅将定长编码检查的最终有效性布尔值标为公开；私钥、熵、掩码和被拒绝候选值保持秘密，秘密分支阳性对照被检出。低内存实际ELF的稀疏及范数助手另有机器码与整数对照。

Windows三容量共144次签名逐字节比较、9次不足容量恢复及四档容量边界检查通过，记录见`requirements-security-windows-01`。高性能DLL为`2f6b15683dd330c519d92067b5da0de21447a5a5e9fd757bd8afae1220dd747e`，低内存DLL为`4f0afdfebf9580e9ab88c12f674de807e09be5e5cb0cf6c32df292991d4e116b`。同目录`machine-code-review.md`给出公开矩阵前缀、固定范数扫描、延迟挑战NTT和公开容量选择的实际函数与分支位置。功能输出比较、容量边界和定点机器码审查分别记录其覆盖范围；Windows未作动态污点验证。

ARM高性能44、65验签将三路公开矩阵生成与公钥、消息哈希共同调度，使用两行矩阵循环缓冲及768字节编码高位暂存区。矩阵条目、消息、公钥、签名及长度均为公开输入；分支和地址由这些公开量决定。正式生产库的边界验证覆盖342组消息、上下文及非法签名条件，共2052次验签调用，检查工作区哨兵、清理、不足容量与恢复；记录见`recovery-arm-compact-02/boundary-validation.xml`。标准向量、差分输出、容量恢复及资源检查位于同根`qualification/`，均绑定上述91ba摘要的实际库。

## Windows高性能小系数编解码

`poly_kl.c` 的 AVX2 小系数编解码按八个系数一组执行，每个多项式固定处理32组。η=2精确读取或写出三个编码字节，η=4精确读取或写出四个编码字节；访问位置、移位量与循环次数由公开参数确定。打包前的范围断言和解包后的范围断言沿用接口约束，非规范编码的解码值与标量实现一致。

两类参数各进行十万轮标量参考比较，并将输入与输出放置在无访问保护页边缘检查读写范围。完整两容量构建分别完成标准向量、差分、容量失败恢复与资源检查。证据位于 `artifacts/recovery-windows-size-01/codec-boundaries` 和同根 `qualification/`，生产DLL摘要为 `2f6b15683dd330c519d92067b5da0de21447a5a5e9fd757bd8afae1220dd747e`。该AVX2实现的独立条件编译检查比较Windows低内存十个C翻译单元，ARM两策略的八个DSA翻译单元及加载节、符号和布局另由 `artifacts/recovery-arm-windows-codec-exclusion-01/` 保存。
