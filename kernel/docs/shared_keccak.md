# 共享Keccak置换

共享实现通过上游FIPS202扩展接口，使ML-KEM和ML-DSA调用同一个 `lc_shared_keccakf1600` 函数。两类SHAKE前端分别处理吸收率、域分离、填充、输出和上下文；置换保留Keccak-f[1600]的25个64位状态字、24轮方程和标准轮常数。

## 构建与调用

使用公开构建入口选择 `compact-rate-shared`，后端为 `portable`，优化为 `Os` 并开启LTO。

```text
cmake -S . -B build/shared-keccak -DLC_CONFIGURATION=compact-rate-shared -DLC_BACKEND=portable -DLC_OPT=Os -DLC_LTO=ON
cmake --build build/shared-keccak
```

共享置换每次循环执行一轮。输入输出、状态地址与循环次数保持标准约定；吸收与挤出继续使用各算法前端。每次调用的状态独立分配，公共函数本身保存只读常数。

链接符号、同地址别名和反汇编记录两类算法的实际调用位置。LTO也可能将对照实现的同内容函数合并到同一地址，因此实体数量以链接结果为准。程序变化同时受到置换循环和机器码布局影响。

## 验证与来源

置换检查逐字比较独立状态输出，并通过跨实现SHAKE向量检查吸收、域分离和挤出。标准接口还执行适用ACVP向量、完整流程、签名字节、隐式拒绝、私钥内公钥哈希检查及正常容量恢复。机器指令检查核对固定状态地址与公开24轮循环；插桩程序和无插桩部署库分别登记身份。

`owner_single.c`沿用mlkem-native Keccak C实现的布尔方程与轮常数，文件头记录原作者、源文件摘要及`Apache-2.0 OR ISC OR MIT`许可；完整条款位于第三方目录。项目实现公共入口接入、单轮循环组织和参数化调用，原有密码原语归属保持完整。

完整操作的输入分组时序结果由独立数据集记录，按秘密字段、公开字段、阳性对照和实际库分别分析。共享函数的构建与程序空间数据从相应公开记录复算；具体入口见 `PROGRAM_SPACE.md`。
