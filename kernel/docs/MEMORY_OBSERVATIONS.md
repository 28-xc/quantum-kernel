# 内存分项与共同容量

算法预留内存由工作区、受保护执行栈、上下文、可写全局与单线程局部存储、相关区外堆相加。全六参数部署分别取工作区和栈需求的最大值，再加入同时存在的固定对象。逐操作峰值、单参数三操作容量和六参数共同容量分别保存。

当前正常容量检查先在宽裕栈预留下测量水位，再按协议保留安全余量，验证声明的栈容量。每个参数的固定种子序列保存三项操作的工作区与栈水位。工作区不足检查按公开接口返回容量错误，随后恢复正常容量，核对输出、对象边界和清理状态。容量试验分别记录每次限制、实际返回和足额恢复结果。

同一上下文实验交错执行六组参数和十八项操作，检查同一工作区身份、连续调用、失败清理与恢复。资源探针通过正常空调用和已知大小的区外堆分配核对计量能力，控制条件的额外分配单独登记。

映像清单直接读取实际PE/ELF节与TLS，可写存储包括链接器及工具链运行时数据。相关堆测量覆盖规定的线程初始化至结束区间；PQClean参考的原堆栈方式单独测量。输入输出对象另列，完整应用预算将这些对象与应用状态、应用栈一并计入。

资源结果通过实际库摘要与完整操作时间关联。原始容量扫描、失败、种子、返回码和全部水位均保留。固定容量用于部署判断，观测水位用于说明各操作的存储贡献；系统映射与进程驻留量采用对应系统统计口径。

实际探针位于 `tests/resources/`，正式功能与恢复检查位于 `tests/normal_capacity/`。公开数据清单列出原样数值记录及相应复算入口，接收方按指定文件摘要核对数据，再重新计算各分项和总量。

完整应用资源使用 `tools/application_resources.py`，计时另用不带堆钩子和栈扫描的 `tools/application_timing.py`。两者绑定同一应用模块和核心库。核心上下文已包含在应用状态中，应用栈已包含核心调用链，汇总时分别计入一次。配置和完整命令见 [固定池应用](enrollment_owner.md)。

当签名决定共同工作区最大值时，密钥生成和验签的四路采样临时区可使用各自剩余工作区。设操作o的原工作区为w_o、迁入临时区为t_o，共同工作区为W；在w_o+t_o≤W时，迁移保持W不变，并减少这些操作的栈需求。共同容量分别取工作区与栈的最大值，因此同时核对十八项操作的两类峰值。Windows与AArch64使用同一规则，具体受影响操作和容量由各平台记录给出。方法与源码入口见[矩阵存储与工作区复用](storage_schedule.md)。
