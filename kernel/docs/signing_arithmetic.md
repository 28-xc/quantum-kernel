# 签名的矩阵缓存与合并约减

本节比较紧凑、48项矩阵缓存、56项矩阵缓存、32位缓存和速度五种配置，并以40项矩阵缓存作同条件对照；各配置使用相同标准参数与接口。矩阵缓存属于一次签名调用，条目由本次公钥种子生成；六组参数的完整时间、运行内存和程序空间分别绑定实际库文件。

32位缓存配置在一次签名调用中保存完整公开矩阵，并在每次尝试中保留变换后的掩码向量。矩阵乘加先累积原始64位乘积，再对每个输出系数执行一次Montgomery约减，乘积结果按24位表示保存。矩阵在调用内复用，秘密变换向量在每次尝试退出时清理。

速度配置按公开参数选择矩阵表示。Windows的ML-DSA-44、65直接保存32位规范系数，ML-DSA-87采用低16位与高8位两个平面；AArch64三组参数均采用分平面表示。两种表示分别使用每多项式1024和768字节，恢复得到相同的规范系数。参数与矩阵索引决定读写方式。

乘法每次处理8个频点，先把该块的全部L行输入读入寄存器，再将K行输出写回同一存储。每行包含1024字节系数和32字节谓词位图，后续直接在该行分解低位。输入与输出依次使用同一工作区，保留64位乘加与合并约减。连续nonce的掩码队列保存同一调用内后续尝试所需的输出，完整所属对象在调用结束时清理。Windows的ML-DSA-65还组合两条公开矩阵流和两条秘密掩码流，按各自SHAKE类型独立填充、置换和取出输出。

48项矩阵缓存按固定列序保留前缀。44与65分别只有16、30项，均保存完整矩阵；87保存48项，其余8项在后续尝试中重新生成。首次尝试仍生成全部56项。以尝试次数$a$计，87的矩阵生成项数为$56+8(a-1)$；40项配置为$56+16(a-1)$。相邻四项共享四路置换，48项对应完整分组边界。各项始终使用标准规定的种子和行列序号。

当前尝试的掩码编码与最终响应采用相同的行宽。48项缓存和速度配置将掩码保存在签名的响应区域，先供矩阵乘法读取，再逐行解码、计算响应并覆盖写回。Windows紧凑配置的65、87也在原采样过程首次产生掩码时保留这些字节，响应阶段直接读取；44保留原工作区对象。每次拒绝立即擦除整个借用区域，成功返回前所有行均已替换为响应。输入输出对象在完整应用内存中一并核算。

低内存Dilithium中的24位表示、按需生成和输出区复用可见Bos、Renes与Sprenkels的研究（[ePrint 2022/323](https://eprint.iacr.org/2022/323)）。这里的具体安排将掩码编码、响应行及每次拒绝的清理顺序连接起来；基础SHAKE、NTT和约减沿用对应上游实现与许可证。

ML-DSA模数为8380417，矩阵系数位于0至8380416，变换系数绝对值小于94279698。向量长度为7时，乘积和绝对值上界为5530721568497664，小于约减输入界17996808470921216。Montgomery约减结果位于[-5477929,5477929]，随后执行`reduce32`。AVX2与NEON分别完成同一整数计算，32位行保存其完整有符号值。

上述界由输入范围和累加长度推导。组件试验与生产程序比较使用各自记录的输入域，具体如下。

## 小系数累加与检查次序

速度配置在调用开始时固定扫描全部秘密小系数的编码，只以完整扫描后的一个合法性结果选择累加分组。合法$\eta=2$系数的绝对值至多2，挑战重量$\tau\leq60$，任意部分和绝对值至多120；完整挑战可在8位有符号表示中累加后扩展。合法$\eta=4$系数按31项分组，部分和绝对值至多124，再扩展为16位合并。三组参数的完整积绝对值分别受78、196和120约束。

内部入口的非规范编码沿用覆盖完整编码域的分组。$\eta=2$的解码值位于$[-5,2]$，25项部分和绝对值至多125；$\eta=4$的解码值位于$[-11,4]$，11项部分和绝对值至多121。完整积绝对值分别至多195、539和300。两平台依据同一合法性结果分派，NEON助手独立接收标准$\eta$与分组长度，保持解码规则和累加范围各自明确。

速度配置先检查响应，再检查所有修正低位行，随后进行$ct_0$和提示计算。44的四行低位也采用这一顺序。每行读取全部256个系数后返回范数结果；逐行退出配置可在首个失败行结束尝试。Windows将挑战NTT放在前两项检查通过之后，AArch64继续用稀疏乘法直接形成$ct_0$。候选接受条件、范数界、提示重量界和候选生成顺序保持一致。安全观察范围与清理条件见[签名安全说明](signing_security.md)。

配置文件显式记录`borrow_sig_y`、`natural_sig_y`、`checked_sparse`、`defer_challenge_ntt`、`parameter_a32`和`early_low_44`。构建工具据此生成实际编译定义，并检查平台、采样次序、缓存表示和工作区预留的配合关系。各功能默认关闭，紧凑配置仅在65、87启用自然保留，原配置对照使用原生成与分组路径。

## 完整调用与安全检查

标准功能记录（见支撑材料实验目录）覆盖Windows和AArch64的十个平台/配置组合；每项分别完成645条适用标准向量、1200组完整流程、900对完整签名及3600次OpenSSL交叉检查。完整签名输入包含标准编码私钥、消息、上下文和随机输入，所有内部缓存均在本次调用中建立和清理。

最终签名安全数据（见支撑材料实验目录）保存两种机制各2016项nonce/暂停边界比较、五种AArch64生产配置各900对签名的重试事件、普通与插桩构建及秘密传播记录。提示重量助手在普通与检测器构建上各执行276600项固定检查；每档900次提示编码均紧接900次接受事件，超重候选在位置编码前清理。

另有375组挑战与$t_0$乘积端点直接调用实际AArch64正式固件，比较96000个系数及范数返回值。四路Keccak来源检查读取最终Windows映像中的1376字节函数，独立推导24轮各通道数据来源。

## 分平面与原位乘积

`tests/representation/inplace_product/run.py`直接包含实际矩阵布局和乘积辅助函数，以NTT域输入检查所有输出系数、输入覆盖顺序和行间保护区。测试中的NTT与排列适配器仅用于注入测试域，独立参考按原始输入使用64位整数计算模$q$乘积及Montgomery比例。AVX2和NEON分别执行同一组规范矩阵端点、稀疏与密集输入、符号交替及固定种子输入；完整密码输出另由标准向量和签名字节比较验证。详细方法与入口见[组件说明](../tests/representation/inplace_product/README.md)。
