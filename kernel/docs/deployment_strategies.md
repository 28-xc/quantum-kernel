# 部署策略、算法参数与实验对照

## 配置层次

1. 算法参数：ML-KEM-512/768/1024、ML-DSA-44/65/87，决定标准格式与安全参数。
2. 平台后端：Windows x86-64、Linux AArch64、CH32V307 和 STM32F407。公共组件由统一工程共享，指令和模数相关算术由专用后端实现。
3. 资源策略：`low-memory` 或 `performance`。每种完整策略均支持六组参数、18项操作。

低内存策略采用紧凑表示、按需生成与生命周期复用；高性能策略利用公开矩阵缓存减少重复计算。`tools/kernel.py` 提供部署入口，`tools/build.py` 及相应配方用于构建和实验复现。

## 构建映射

| 平台 | 低内存策略 | 高性能策略 |
|---|---|---|
| Windows x86-64 | `native-x86-low-memory` | `native-x86-performance` |
| Linux AArch64 | `native-arm-low-memory` | `native-arm-performance` |
| CH32V307 | `compact-direct-twiddles` | 64 KiB 用 `partial64`，80 KiB 用 `direct-twiddles` |
| STM32F407 | 独立参数的紧凑固件 | 独立参数的缓存固件，ML-KEM 保留两行、签名最多缓存四个展开多项式 |

CH32的64 KiB和80 KiB布局属于同一高性能策略，从相同公共组件与专用后端构建。工作区在编译时确定，静态RAM由链接结果核算；改变布局需要重新构建与烧录。

## 主机资源规划接口

`include/lattice_resources.h` 提供以下接口：

- `lc_resource_query`：查询指定参数、操作的充分工作区边界、推荐容量、对齐及规划对象大小。
- `lc_resource_make_plan`：按实际工作区地址与容量选择布局，检查对齐损耗及溢出。规划结果与完整签名执行采用同一选择规则。
- `lc_resource_algorithm_bytes`：对调用者提供的工作区、栈和其他运行存储数值执行带溢出检查的合计。栈与应用对象需分别核定后传入。

操作编号0为密钥生成，1为封装或签名，2为解封装或验签。未知参数或操作返回−1，裁剪构建移除的合法操作返回−8，容量不足返回−5；失败时清空查询输出。规划依据公开容量与对齐信息，在秘密数据解码前完成。

ML-DSA-87签名支持两档缓存：充分对齐工作区达到57,024 B时使用完整56个多项式缓存；42,944 B至该容量之间使用五行35个多项式缓存，其余行按需生成。其他操作采用固定布局。所列Windows与ARM高性能构建的六参数18操作共同查询容量均为42,944 B。ML-DSA密钥生成的固定分配由实现单元按对象尺寸和对齐计算，容量边界通过足量、少一字节拒绝、输出清零及恢复检查。裁剪、宏选项或平台变化后，应按对应构建查询需求。

查询与计划结构由调用者提供，保留时计入应用预算。算法RAM包括工作区、栈、64 B上下文、可写全局/TLS及外部分配；完整应用另计密钥、签名、密文、消息、应用状态和调度开销。两条缓存路径的程序空间按同一库文件核算。

## 实验对照与扩展接口

| 配方或固件 | 技术角色 |
|---|---|
| `native-x86` / `native-arm` | 紧凑流式低内存对照：24位表示、低位压缩、流式矩阵与工作区复用，Os/LTO构建 |
| `*-cache48-*` | 固定部分矩阵缓存的机制与资源对照 |
| `*-whole-row64` | 主机矩阵行缓存和原位输入复用的布局对照 |
| `*-sign-pipeline` | 固定完整缓存的高性能对照 |
| `*-public-a-session` | 公钥重复使用的独立会话接口，分别核算准备时间与保留缓存 |
| CH32 `compact` / `compact-direct-twiddles` | 32 KiB 逐层完整表对照 / 融合直接表部署 |
| CH32 `partial64` | 64 KiB完整RAM预算下的部分缓存部署 |
| CH32 `cached` / `direct-twiddles` | 80 KiB 完整缓存，分别使用融合半表对照 / 融合直接表部署 |

低内存联合机制实验将上述紧凑流式对照与部署策略比较，报告完整实现的联合效果。各配方的源码、构建命令与程序摘要由对应实验记录绑定。主机部分缓存配方与CH32 `partial64` 分别按各自布局核算。

CH32公共组件通过源码映射直接引用主工程文件，模数、系数表示和处理器指令相关部分使用专用实现。构建核对生成映像与已验证固件的字节身份。

## 测量与使用条件

规划器覆盖所列经过验证的离散布局。完整操作时间按平台分别测量，同一构建的时间、算法内存和程序空间共同形成资源取舍结果。每组比较绑定编译器、测试驱动、输入与基线身份。

标准向量、组件和软件时序结果的覆盖范围见报告第4章及对应验证记录。CH32栈界采用固定时钟、随机回调和中断安排；移植时须按目标调用与中断条件重新核算。
