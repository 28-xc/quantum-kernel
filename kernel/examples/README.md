# 设备公钥签发与密钥建立

固定内存池、签名缓冲区复用及完整生命周期检查见[完整应用说明](../docs/enrollment_owner.md)，使用 `tools/application_owner.py` 构建和复现。

`enrollment.c` 将 ML-DSA 和 ML-KEM 串联为一个设备接入流程：签发方签署设备新生成的 ML-KEM 公钥，接收方验签后封装共享秘密，设备解封装并核对结果。各步骤顺序执行，共用一个上下文和工作区。

## 完整流程

1. 生成签发方 ML-DSA 密钥。
2. 生成设备 ML-KEM 密钥。
3. 使用 ML-DSA 签署设备 ML-KEM 公钥。
4. 验证该签名。
5. 使用设备公钥封装共享秘密。
6. 使用设备私钥解封装，核对两端共享秘密并清理临时秘密。

示例支持 512/44、768/65、1024/87 三组参数搭配。签名消息直接引用设备公钥缓冲区；上下文为 26 字节 ASCII 字符串 `A1-27 device enrollment v1`。身份密钥可在批次开始时生成并复用，也可在每次流程中重新生成。后一模式包含两类算法的全部六项操作。

## 构建与运行

在工程根目录编译。以下命令为紧凑实现运行一次完整六步流程，工作区为该实现六组参数共用的 10720 B：

```text
gcc -O2 -std=c11 -I include examples/enrollment.c -o enrollment
enrollment path/to/latticecore.dll 768 65 10720 1 1 0 0 example.csv
```

Linux 编译时附加 `-ldl`，运行时使用对应 `.so` 文件。九个命令行参数依次为：

|参数|含义|
|---|---|
|算法库|动态库路径|
|ML-KEM 参数 / ML-DSA 参数|例如 768 / 65|
|工作区字节数|所选实现的固定工作区容量|
|运行次数|测量流程次数，范围 1–10000|
|重新生成身份|1 为每次生成，0 为批次内复用|
|测试种子|0 使用系统密码随机源；非零值使用可重复测试输入|
|逻辑处理器编号|绑定本机可用处理器|
|CSV 文件|逐次结果的输出路径|

每次程序启动先执行十六次预热，再执行指定次数。生产调用使用系统密码随机源；非零种子用于实验中比较相同输入。

## 结果与测量范围

CSV 保存迭代号、预热或测量标记、完整流程耗时和工作区使用峰值。终端 JSON 给出参数、身份生成方式、序列化对象总量、工作区容量、上下文大小、随机字节请求量、批次时间及公开输出校验值。

逐次计时包含上下文初始化、所选模式中的密钥生成、签名、验签、封装、解封装、秘密比较和临时秘密清理。批次时间另包含公开输出校验值的计算。复用身份模式在批次开始前生成身份密钥。

该例程为输入输出对象和工作区申请内存，同时保存计时记录。资源数据分别列出对象、工作区、栈及其他存储。

批量比较入口为 `tests/application_workload/run.py`。它对各实现使用相同测试种子，核对公开输出校验值，并记录完整流程的耗时分布与批次吞吐量。各被测实现使用相同调用流程，替换库文件和工作区容量即可比较。

## 固定总预算实验

`tests/application_workload/resource_probe.c` 将上述六步流程放入单一固定内存池和受约束应用栈中执行。预算包括全部序列化对象、应用状态、对齐填充、工作区、完整应用栈、库的可写全局与单线程局部存储，以及应用的全局调度指针。应用状态已含密码上下文和函数表。域字符串计入只读程序空间。

批量入口为 `tests/application_workload/resources.py`。配置文件指定算法库、SHA-256 和该库的六参数资源记录，驱动逐一运行三组参数搭配及给定预算：

```text
python tests/application_workload/resources.py --configuration application_resources.xml --output D:/application-resource-results
```

驱动创建新的输出目录。每次尝试保存条件、返回码、已完成操作数、内存使用、边界状态和输出比较结果，同时保留容量不足记录。栈越界与堆分配控制检查用于确认测量工具能够观察相应事件。固定预算实验记录功能与资源结果，执行时间由前述独立计时驱动测量。
